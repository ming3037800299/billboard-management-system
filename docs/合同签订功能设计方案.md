# 合同签订功能设计方案

> 对应 11 月第二次周报第 3 项：合同签订功能的需求梳理与方案设计。
> 方案已在项目中落地为「预定与合同（预览版）」，本文件记录业务规则、状态流转与实现约定，供后续确认与扩展。

## 1. 目标与范围

广告牌租赁从「选定点位」到「完成签约」需要一个可追踪的闭环：

1. 后台选中广告牌发起预定，锁定点位，避免重复出租；
2. 按模板生成正式合同（Word），自动写入甲方、乙方、广告牌与租期信息；
3. 生成签署链接 / 二维码交给乙方，乙方免登录查看并电子签署；
4. 签署完成的合同归档，支持下载、作废、提前终止与到期自动结束。

本期范围：合同模板管理、合同生成、签署链接与在线签名、归档、作废 / 结束。续签仅保留设计（复用预定流程新建合同），不在本期实现。

## 2. 角色

| 角色 | 能力 |
|---|---|
| 甲方（管理员） | 维护签约主体与电子签章、管理模板、发起 / 生成合同、复制链接或二维码、上传线下回签件、作废 / 结束合同、下载全部版本 |
| 乙方（承租方） | 通过签署链接查看合同要素、手写签名或上传签名图片、上传线下已签合同、下载当前合同 |
| 系统 | 预定锁点、占位符渲染、签名嵌章、状态流转、到期自动完成、事件留痕 |

## 3. 合同要素

- 甲乙方信息：甲方签约主体、地址、联系人、电子签章；乙方名称、主体类型（企业 / 个人）、联系人、联系电话。
- 广告牌信息：编号、名称、所在公路、路段、详细地址、尺寸、材质、可视面积、单价快照。
- 投放约定：投放起止日期、租期、租金总额、定金、付款方式、广告内容。
- 合同信息：合同编号、签订地点、签订日期、当前日期。
- 签署信息：签署人、签署时间、来源 IP、签名图片、签署链接有效期。

> 预定创建时对广告牌关键字段做快照，后续广告牌资料修改不影响已生成合同。

## 4. 签署流程

```
选定广告牌 → 创建预定（广告牌 RESERVED）
          → 生成合同（PENDING_SIGN，渲染 docx + 保存模板副本）
          → 复制签署链接 / 二维码
          → 乙方打开 /sign/{token}（免登录）
          → 手写签名 / 上传签名图片 → 嵌入合同生成最终 docx（SIGNED）
          → 归档；到期或管理员操作 → COMPLETED（释放广告牌）
```

- 签署链接默认 7 天有效，可在「签约设置」调整；重新生成链接会使旧链接失效。
- 链接只读查看与文件下载同样校验「撤销 + 过期」，过期链接不再返回合同内容。
- 乙方也可上传线下已签合同（PDF / JPG / PNG / DOCX），直接进入已签署状态。

## 5. 模板与占位符

- 模板为 `.docx`，在「系统管理 → 签约设置」上传、启停、设为默认。
- 文本占位符：`{{字段名}}`，字段清单由后端统一提供（合同编号、甲乙方、广告牌、租期、金额等）。
- 图片占位符：`{{@甲方签章}}`、`{{@乙方签名}}`，模板必须同时包含，否则不允许启用。
- 生成时把模板、甲方签章、数据快照一并保存为合同文件版本，保证历史合同可复现。
- 金额同时输出数字与大写，避免手写歧义。

## 6. 数据模型

| 表 | 作用 |
|---|---|
| `contract_settings` | 甲方签约主体、地址、联系人、电子签章、默认模板、签署链接有效期 |
| `contract_template` | 合同模板文件、名称、启停、默认标记、识别到的占位符 |
| `reservation` | 预定记录：广告牌快照、乙方信息、租期、租金、定金、付款方式、广告内容、状态 |
| `contract` | 合同主表：合同号、预定 ID、签署 token、token 有效期 / 撤销标记、状态、签署人 / 时间 / IP、当前文件 |
| `contract_file` | 合同文件版本：模板副本、生成稿、签名图、最终稿、线下回签件 |
| `contract_event` | 关键事件留痕：创建预定、生成合同、签署、上传、作废、完成等 |

## 7. 状态流转

**预定（reservation）**

```
CONFIRMED（已预定/待签） → SIGNED（已签约） → COMPLETED（已完成）
        ↘ CANCELLED（已取消，释放广告牌）
```

**合同（contract）**

```
PENDING_SIGN（待签署） → SIGNED（已签署） → COMPLETED（已完成）
        ↘ VOID（已作废，释放广告牌）
```

**广告牌（billboard）**

```
AVAILABLE → RESERVED（存在未完成预定） → RENTED（已签约） → AVAILABLE（完成/作废/取消）
```

规则：

- 同一广告牌同一时间只允许一条未完成预定；预定成功后其他客户不可再预定。
- 未签合同取消后释放广告牌；已签合同作废需要填写原因并留痕。
- 合同结束日期过后由每日定时任务自动完成并释放广告牌；也可管理员提前结束。
- 「已预定」状态的广告牌不允许通过普通编辑改回「可租赁」，必须走取消 / 作废流程。

## 8. 存储与安全

- 合同、模板、签章、签名存放在私有目录（默认 `uploads-private/`，可用 `CONTRACT_DIR` 覆盖），不映射为静态资源。
- 仅管理员令牌或有效签署 token 可读取；文件名使用 UUID，路径做越界校验。
- 签署 token 使用随机串，支持刷新（撤销旧 token）与过期时间；签署记录保留姓名、时间、来源 IP。
- 管理端列表只返回必要字段，文件下载单独鉴权。

## 9. 异常场景

| 场景 | 处理 |
|---|---|
| 乙方重复签署 | 状态不是「待签署」时返回业务错误，不覆盖已有签名 |
| 签署链接过期 / 被撤销 | 查看、下载、签署均拒绝，提示联系甲方重新获取 |
| 合同作废 | 需填写原因，合同转 VOID，释放广告牌，保留文件与事件 |
| 提前终止 | 已签合同可提前结束，转 COMPLETED 并释放广告牌 |
| 模板缺占位符 | 保存模板时校验并提示，禁止启用 |
| 合同文件缺失 | 生成 / 下载时返回明确业务错误，不抛 500 |
| 续签（后续） | 复用预定流程，以原合同快照为默认值新建合同，旧合同按到期或终止处理 |

## 10. 接口概览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET / PUT | `/api/admin/contract-settings` | 甲方主体、签章、链接有效期 |
| GET / POST | `/api/admin/contract-templates` | 模板列表 / 上传 |
| POST | `/api/admin/contract-templates/{id}/default` | 设为默认模板 |
| DELETE | `/api/admin/contract-templates/{id}` | 删除模板 |
| GET / POST | `/api/admin/reservations` | 预定列表 / 创建 |
| PUT | `/api/admin/reservations/{id}` | 编辑未完成预定 |
| POST | `/api/admin/reservations/{id}/cancel` | 取消预定并释放广告牌 |
| POST | `/api/admin/reservations/{id}/contracts` | 按模板生成合同 |
| POST | `/api/admin/reservations/{id}/signed-contract` | 后台上传线下已签合同 |
| GET | `/api/admin/contracts` | 合同档案 |
| POST | `/api/admin/contracts/{id}/refresh-link` | 刷新签署链接（旧链接失效） |
| POST | `/api/admin/contracts/{id}/void` | 作废 |
| POST | `/api/admin/contracts/{id}/complete` | 提前结束 |
| GET | `/api/admin/contracts/{id}/download` | 下载当前版本 |
| GET | `/api/admin/contracts/{id}/files/{fileId}` | 下载指定文件版本 |
| GET | `/api/sign/{token}` | 乙方查看合同要素 |
| GET | `/api/sign/{token}/file` | 乙方下载合同 |
| POST | `/api/sign/{token}/sign` | 在线签名 |
| POST | `/api/sign/{token}/upload` | 上传线下回签件 |

## 11. 验收标准

1. 预定后广告牌锁定，其他客户无法预定；取消后恢复可租。
2. 生成的 docx 包含广告牌、甲乙方、租期、金额与签章，金额大写正确。
3. 签署链接可免登录打开，签名后最终 docx 内含签名图片与签署人信息。
4. 过期 / 撤销链接无法查看、下载或签署。
5. 作废 / 结束合同后广告牌状态正确释放，事件表有完整留痕。
6. 模板缺图片占位符时无法启用，接口返回明确提示。
